02 — System Flowchart
Device Powers On / Connects
New or existing IoT device joins network
▼
01
Passive Rhythm Capture
Collector silently measures packet inter-arrival times, clock drift, latency jitter over 30-second window. No agent. No device modification.
▼
02
Profile Exists?
Check distributed neighbor mesh for existing hardware rhythm profile
NO — ENROLL
YES — VERIFY
Enroll New Device
Capture baseline rhythm over 10-min window. Generate statistical fingerprint (μ, σ, drift coeff). Store compressed profile (~4KB) in neighbor mesh. Issue enrollment certificate.
Retrieve Rhythm Profile
Fetch stored statistical signature from nearest neighbor node. No central DB call needed.
▼
03
Issue Ephemeral Challenge
System requests 10-second live behavioral sample from device. One-time token — cannot be pre-computed. Hacker cannot fake real-time hardware physics.
▼
04
Rhythm Attestation
Compare live rhythm vs stored profile using Mahalanobis distance. Check: oscillator drift match, packet jitter pattern, power signature correlation. Compute attestation confidence score.
▼
05
Attestation Confidence ≥ Threshold?
Threshold is context-sensitive: 95% for medical devices, 80% for office sensors, 70% for guest devices
FAIL — BLOCK
PASS — ALLOW
🚨 Block + Alert
Connection denied. Device quarantined. LLM generates incident narrative. Alert dispatched to IT/SIEM. Rhythm mismatch evidence logged.
✅ Allow + Monitor
Connection permitted. Continuous passive monitoring begins. Drift detection runs every 30s. Profile updated incrementally.
▼
06
Continuous Drift Monitoring (LSTM)
LSTM model tracks rhythm evolution over time. Natural drift (aging hardware, temperature) is learned and tolerated. Sudden drift = anomaly flag.
▼
→
Loop: Re-attest Every 30 Seconds
Attestation is not a one-time gate — it's continuous. A device that passes at 9 AM but gets swapped at noon is caught at 9:01.
